## 1. Founder rules (binding; do not relitigate)

- **Positioning:** HelloGrowthCRM is a broad AI CRM suite (about 456 features, 500+ integrations, 33+ verticals). Never "WhatsApp-first" or "just a WhatsApp CRM".
- **Pricing:**
  - One plan, Growth: **$12/user/month in the US** and **₹899 in India**. HGC cells are never "higher tier".
  - The Free Forever plan is confirmed.
  - The "$10 annual" price is still open.
  - Local prices are USD 12 converted and rounded: A$17 and NZ$21 (2026-10-29). Whether GST is inclusive or exclusive is still open.
- **Claims:**
  - Never downgrade an HGC claim without code proof. Records lag shipped features.
  - Reuse first: grep hellocrm before writing that HGC lacks something.
  - A missing feature becomes a hellocrm plan PR with a token estimate. If it is T2 or at most 7.5M expected tokens, mark it `coming_soon` in `comparison-graph/hellogrowthcrm.csv`.
  - A capability covered by a live integration is marked `integration` ("via X").
- **Copy:**
  - No competitor list prices in page copy; they belong in research data only.
  - No FAQPage schema.
  - No "best", no percentage savings, no unverified badges.
  - Review requests go to every customer; never gate reviews; never Yelp.
- **Privacy:** no person-level visitor identification. RB2B and Warmly webhook leads are fine. Visitor tracking is `coming_soon` and switched off fleet-wide.
- **Ahrefs is PAUSED** (founder, 2026-10-29: "do not use ahref for now"). Live reading: 2,747 of 800,000 units left, reset 2026-11-26. Use Google Ads Keyword Planner for keyword demand.
- **Firecrawl** credits are free; use it where curl is blocked or a page is JS-rendered.
- **Style:** Indian English, absolute dates, concise.
- **Restricted areas** (auth, billing, migrations/RLS, secrets, email sending) need the founder to **name the area** ("Authorised-Area: …"). A blanket "all permissions" does not unlock them.

## 5. How to run the research in an AI-efficient way

This is condensed from skill §0 and §8, which hold the full rules.

1. **Repository first.** Before any external call, check `research-manifest.json`, `research-index.jsonl`, the entity's files and `growth/master-opportunity-ledger.csv`. If the data is fresh, reuse it. If it is partial, fetch only the missing fields. If it is stale, refresh only the expired fields. Freshness classes: fast 30 days, medium 90, slow 180–365. AI answers are fast class (7 days for P0 prompts).
2. **Cheapest tool first:** scripts → free APIs (MCP Registry, curl, Firecrawl, Keyword Planner) → small model in batches of 50–200 with validated JSON → strong model only for synthesis, once per competitor or cohort.
3. **Three layers, never mixed:**
   - raw: `raw/<tool>/<slug>/<market>/<report>/<date>`, never edited;
   - structured: CSV/JSON rows, each with a `source_id`;
   - synthesis: Markdown, written last.
4. **Register everything:** sources in `sources/source-registry*.jsonl`; cost in `operations/research-cost-ledger*.csv`; actions in `operations/research-log*.jsonl`; opportunities via `merge_opportunities.py`.
5. **Model routing:**
   - Haiku, or no model at all, for scripts and counts.
   - Sonnet for per-competitor write-ups and page builds.
   - Opus or Fable for plans, judgement and synthesis.
   - Fable for voice and blind review.
   - Sol, then fold, then blind Astra for T2+ plan reviews.
6. **Measured costs** (2026-10-29):
   - SEO cohort: about 8–10k tokens per competitor.
   - Capability plan PR: about 260–290k tokens.
   - Compare-page batch of 10: about 300–500k tokens.
   - C0 self-crawl: about 300k tokens, with 0 Ahrefs and 0 Firecrawl.
7. **Graphify for code questions** ("does HGC have X?"). Build a local AST graph of hellocrm or hellocrmwebsite (`graphifyy[sql]==0.9.71`; `graphify extract . --code-only`). It is about 2k tokens per question against about 180k for grep-and-read. Never use it for RLS questions, and never commit `graphify-out`.
8. **Parallelism:** 5–10 agents, never two on the same files; each works in its own `git worktree` off the remote branch. Agents report in at most 300 words; the details go in committed files.
9. **Gates:** every plan or build goes through `/rss-plan-pr` (hellocrm) or `/plan-pr` (website) with the repo gate skills. Draft PRs only; never merge.
10. **End every session** with the §0.10 checklist: reuse, new evidence, storage, sources, ledger changes, HGC assets mapped, cost, next refresh, next action.
